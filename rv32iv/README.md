# rv32iv: RISC-V core with a vector unit

An RV32I+Zmmul 5-stage core with an in-house Zve32x vector unit (VLEN = 128, 4 lanes), its memories and an APB CSR
block (top `m_soc_top`). The example firmware runs a pre-trained INT8 MLP (784 → 128 ReLU → 10) that recognizes a
handwritten MNIST digit. The target is an Intel Arria 10 (10AX115N2F40E2LG) at 200 MHz.

The design was generated by **Q3TUI**, the multi-agent chip design platform, from one hand-written intent document
(`spec/intent.md`): the specification, the RTL, the testbench, the firmware and the constraints. The flows ran with
their review gates approved automatically and their open questions answered with the defaults they proposed.

## What Q3TUI produced

| Flow | Steps | Result |
|---|---|---|
| spec | spec → parse → config | `spec/spec.md` (21 sections), 87 requirements (`schemas/structured_spec.json`), the configuration (`schemas/final_config.json`) |
| rtl | rules → csr → rtl → format → style_lint → smoke | 38 RTL modules (~7,300 lines) in `src/rtl/`, top `m_soc_top`; the CSR block from the APB-CSR-Generator; Verible format and style lint clean; smoke test pass |
| dv | testplan → tb → prepare → simulate | a 60-test plan (`schemas/test_plan.json`), a SystemVerilog testbench (`src/tb/`), firmware and test programs (`src/sw/`); **59/59 simulated tests pass** (`reports/dv_test_results.md`) |
| fpga | fpga_port → sdc → fpga_synth → timing_util_report → ppa_optimize | Quartus Prime Pro 25.1 post-synthesis: **WNS +0.416 ns at 200 MHz (Fmax ≈ 218 MHz)**, 8,690 ALMs, 6,646 registers, 10 DSP blocks (`schemas/ppa_report.json`) |

The failing simulations and the missed timing along the way were triaged by Q3TUI and fixed by its own RTL and
testbench agents (the fix loops of `simulate` and `ppa_optimize`).

## Folders

| Folder | Holds |
|---|---|
| `spec/` | `intent.md` (the input, written by hand) and `spec.md` (the specification Q3TUI wrote from it) |
| `schemas/` | the structured spec, the configuration, the test plan, the simulation evidence and triage, the FPGA reports; `questions/` the questions each step asked and how they were settled |
| `src/rtl/` | the RTL; `csr/` the CSR generator's input and report, `smoke/` the smoke test, `style_lint/` the Verible flags and rule checks |
| `src/tb/` | the testbench (`tb_top.sv`, one file per test in `tests/`, `run.sh`) |
| `src/sw/` | the MNIST firmware, its linker scripts and build scripts |
| `constraints/sdc/` | the SDC (clocks, I/O delays, exceptions) shared by the FPGA and the sanity flows |
| `reports/` | the test results table |
| `reviews/` | the review records of the spec flow |
| `config/tools.json` | the EDA tools by role (VCS, Verible, Quartus, VC Static, RISC-V GCC, Spike); install paths and the license server are left out |
| `q3tui.yaml` | the project settings Q3TUI ran with |

Q3TUI's internal state (`.q3tui/`) and tool output (`build/`) are not included.

## Running it again

With Q3TUI installed, in this folder:

```sh
q3tui tools init     # or adapt config/tools.json to your machine (tool paths, license server)
q3tui                # the TUI; or `q3tui auto` for the full unattended run
```
